# TV-owned picture profiles (0.18)

The TV stores and restores standards. Home Assistant supplies day/night context and a named-profile selector, provides the same editor, and stores complete backups. Existing native input, range and ALLM mappings select presets. HDMI source routing, CEC filtering and Nintendo no-signal shutdown are independent and unchanged.

## Daily operation

Open **Picture settings** in the TV app or **LG Picture Profiles** in the HA sidebar. Two cards stay at the top. **Editing** is a tab strip (**Base**, then each named profile) whose accent colour is the save destination: teal for Base, violet for a profile. **On TV now** shows the input, preset and signal on screen and the profile the TV is using. Changing the edit destination never selects a viewing profile; **TV profile & automation** does that separately.

The editor opens on what the TV is showing, like LG's own menu, but any target can be edited. The **settings list** shows each setting's value for the current targets: a number, a range such as 50–55 when targets differ, **n/a** where LG does not use the setting, or **—** where it is not stored. Choose a setting to open its **value control** and its **target grid**. Grid columns are inputs and rows are presets grouped as SDR, HDR and Dolby Vision. Preset selection uses signal rows (with and without ALLM), and HDMI connection settings use one row with one column per port. Each cell shows that target's stored value.

Targets are inputs × rows. Choose a cell to edit just that target. Toggle a column header for an input, a row header for a preset, a format header such as **Dolby Vision** for all of its rows, or the corner (**All inputs**) for every column. For example, the Dolby Vision header plus **All inputs** edits every Dolby Vision preset on every input, and deselecting two columns narrows it to the other ports. **On screen now**, **Everything shown**, **All Game presets** and **All movie presets** are shortcuts. The selection carries across settings, so you can also pick targets first and then walk the list. The value box names the selection in words, such as “HDMI 3, HDMI 4 · all Dolby Vision presets in use”. Choosing targets never changes the TV input, creates native banks or applies a profile.

The native settings catalog is a RAM-only index of model-specific storage scopes and controls. It discovers supported SDR, HDR and Dolby Vision presets, video/PC input identities and Game Optimizer genres without enrolling any values. The editor reads the visible selection and its dependencies on demand. Refreshing or browsing does not write a profile file or any native setting. Hidden presets, excluded controls and the existing audited availability restrictions still apply.

**Base** combines native-only values with deliberately managed standards. Editing a native-only Base value writes LG’s exact saved location using a compared, verified write; it does not create a standard. Adding its first named-profile override or brightness link captures only that key’s current native baseline. Existing managed controls keep temporary adjustment tracking and power-cycle restoration. Native-only controls keep LG’s normal persistence until explicitly enrolled.

The persistent collection therefore contains only managed keys, overlay values and brightness links. A separate complete `native_snapshot` is captured in RAM after startup/power-on restoration, then updated by existing observations and native reads/writes. It is published with the managed collection to Home Assistant; there is no native snapshot file on TV flash, no periodic full scan, and no additional settings polling. `captured_at` identifies the last complete scan; `updated_at` identifies the latest observed value change. Before the first scan succeeds, the snapshot is explicitly null; HA preserves its preceding complete backup. An explicit `capture_native` refresh is available when needed. Restoring a complete backup writes native-only values through a transient recovery intent without enrolling them in profile management.

By default each port shows the input identity it actually uses (LG's PC-labelled bank on the PC's port, ordinary video banks elsewhere). **Show PC and video inputs separately** shows all eight. Port-wide connection settings and Game Optimizer genre values remain shared by both input types of a port. Rows default to presets an input's preset selection recalls (in Base or any profile), presets with managed values, drafts and the on-screen preset. **Show N more presets** reveals every preset LG offers, including Expert / ISF. Faded cells are presets that input does not currently select; they are still editable. Where a setting has Game Optimizer storage, **Game Optimizer genres** and **ALLM** chips narrow which genre/ALLM banks a Game-row edit includes (all by default).

An edit is never permission to change a target where the setting is disabled or unverified. Those cells show **n/a** with LG's reason, and the value box reports how many selected values are skipped and why. The control uses the intersection of every included target's native choices or range, and waits until all of them have been described. If there is no common range or choice (for example, preset selection across formats), the value box asks you to narrow the selection. Linked SDR brightness is one shared value. Selecting any linked preset also changes its partners: they are outlined dashed in the grid and named in the value box. **Exact TV storage** lists the native targets for the selection. Apple TV and Shield share movie banks; Switch uses Game Optimizer banks on the same port. A broad edit changes the listed existing values once; it does not create an inheritance rule for future banks.

The settings list is grouped into sections:

| Category | What it contains |
| --- | --- |
| **Picture** | Color, sharpness, contrast, black level and other picture controls. Equivalent Game Optimizer controls join the same row. |
| **Motion** | Real Cinema, TruMotion and other configured motion controls. Real Cinema remains stored in LG's ordinary picture bank. |
| **Game Optimizer** | Distinct Game Optimizer controls, such as stabilizers, fine tune dark areas and the port's genre selector. |
| **HDMI connection** | Port-wide options such as ALLM, VRR, QFT and refresh-rate boost. All connected devices and formats share them. |
| **Preset selection** | Which picture preset LG selects for each input and signal range, including ALLM and dormant mappings. |

Grid markers: a filled outline is selected; a dashed outline is a linked partner the edit also changes; a blue dot is on screen; a violet diamond is an override in the profile being edited (an outlined diamond, while editing Base, means a profile keeps its own value there); a short bar is linked SDR brightness; an amber dot is a temporary adjustment on the TV; hatched **n/a** means LG does not use the setting there. On the TV remote, arrow keys move spatially (the grid moves in two dimensions), OK selects a target or starts editing a value, and Back ends editing, then closes a review or side view.

Descriptions beneath each setting name explain its effect and relevant tradeoffs. They also clarify LG’s terminology, including VRR & G-Sync and Prevent input delay. [Sources and native mappings](setting-help.md) document the G6-specific meanings.

Values remain drafts across setting, target and destination changes, with their original exact targets. Drafted cells and list entries are marked, and the footer counts staged changes and their destinations. **Review changes** lists only the changed fields, their before/after values and their original targets. **Save Base**, **Save [profile] overrides**, or **Save all reviewed changes** identifies the destination explicitly. The batch validates completely before saving. Managed edits commit one standard revision; native-only edits keep their normal LG persistence. Base reviews list profiles that follow the new value and profiles whose overrides stay unchanged. Native writes run through the existing verified recovery journal; a saved batch can have pending TV application if a native write fails. Uncommitted drafts survive failures. An editor conflict requires another explicit review against the latest standards.

When selected targets have a temporary adjustment, the value box shows it with **Restore saved value** and **Keep adjustment**. **TV profile & automation** lists every temporary adjustment with **Restore all to saved values** and **Keep all adjustments**. Each action requires a preview and acts on the listed setting keys, not whole LG banks: restoring Real Cinema never touches Contrast in the same bank. Keep promotes only tracked temporary values and verifies they have not changed since review. A room or active-profile change invalidates an open restore/keep preview. These actions use the active profile shown in the preview; the Editing tabs control which saved values you edit.

Reviewed G6 profile rules and TV descriptions supply supported options and numeric limits. Audited Gamma, console HDR processing and gaming port preferences remain editable while their inputs are inactive; verified unsupported controls stay excluded. Switching input does not discard the completed audits. [Applicability evidence](setting-availability.md) records the model/firmware boundary and untested signal cases. A combined control uses the intersection of its targets' valid choices and waits for all required metadata. Metadata is read on demand for the selection, the open setting's visible grid, linked partners and each input's preset mappings. It is batched (up to 32 groups per request) and cached until a refresh, save or destination change; overlapping reads never request a group twice. **Refresh** explicitly rereads it. There is no background editor polling. Tracked deviations show **Temporary**, and offline views show the saved backup without editing.

OLED pixel brightness is one setting across SDR, HDR and Dolby Vision rows. HDR/Dolby Vision controls remain editable per native profile with TV-reported limits. Base standards define shared SDR movie and gaming brightness. Each named profile can override either value; unmodified values inherit from Base. Base movie brightness is editable. In **SDR brightness links** (under OLED pixel brightness, for the selected SDR presets), each SDR picture profile can join or leave its shared group. Unlinking freezes the effective standard, preserves temporary adjustments and copies the base and every named profile’s effective brightness; it does not change the current picture. Independent brightness supports per-input/preset and profile edits like any other target. Relinking previews and adopts the existing shared preference. These controls always preview their full affected set, even outside the selected ports. The companion's existing three standard-brightness numbers edit Base gaming brightness and the profiles bound to automatic bright/dark movie brightness and become unavailable when no profile uses that group. Ordinary MQTT setting sliders remain temporary controls.

LG stores ordinary picture values, including Real Cinema and TruMotion de-judder/de-blur, by input and picture preset. Only `truMotionMode` also uses the matching `com.webos.app.hdmiN` app scope. Game Optimizer values use physical input, signal-format/ALLM and game genre. The editor groups these for presentation while preserving their true storage identities. Refresh-rate boost uses the TV's reported panel rate (165 Hz on the verified G6), without changing the internal key or entity ID.

**Include TruMotion adjustments** enrolls missing de-judder/de-blur values from the existing native movie banks in one revision, preserving all other standards and temporary changes. Both values use 0–10, step 1, and are editable after saving TruMotion User Selection for that preset; Game profiles exclude motion interpolation. Repeating enrollment writes nothing.

Only keys defined in the collection are managed. Remote changes never teach a new standard automatically. Preset mappings are validated against their format and the TV’s offered choices. Game genre banks remain editable independently of the currently mapped preset; they are used when the matching Game preset and genre are selected. Picture banks are shared across ALLM states. Panel-specific white balance/CMS calibration is not imported.

## Named profiles

The **Base** tab edits the starting values; a profile tab edits that profile's overrides. Each profile value has an **Edit Base** shortcut that keeps targets, the open setting and drafts and focuses the Base value. **Follow Base** (remove override) makes the selected targets follow Base again; it does not change Base. New profiles inherit every base setting; editing a value pins an override in that profile. Changing a base value updates profiles that still inherit it. The value box states whether the selection follows Base or overrides it, and grid cells mark overrides. **Show only overrides** lists every setting the profile changes. **Manage profiles** supports New from Base, and for the profile being edited, Duplicate, Rename, Reset to Base and Delete. Duplication copies only the source’s overrides; it does not snapshot inherited base values. Reset clears all overrides. In Home Assistant the same view (**Profiles & backup**) offers backup download and import.

**TV profile & automation** contains **Profile to apply** and **Apply profile**, which choose what is used on the TV, along with the automatic bright/dark bindings and the profile management switch. Creating or editing an inactive profile does not activate it. Deliberately applying a profile compares all managed native settings and clears temporary adjustments; only differences are written. Edits to the active profile apply the changed standards. Management must be on to perform native writes. A selection made while management is paused or the bridge is running in standby remains queued for resumption/power-on.

**Automatic** selects the profile bound to bright/dark room context from HA. Bright room and Dark room migrate with exactly their previous effective values. Automatic transitions preserve temporary adjustments. Manual selections persist across sunsets, standby and bridge restarts until you select Automatic again. Assign any named profile or Base to either automatic binding. A bound profile must be unbound before deletion; deleting the manually selected profile returns to Automatic.

HA’s **Picture profile** select updates from complete backups whenever profiles are created, renamed or deleted. The `lg_picture_profiles.apply_profile` action accepts a stable `profile_id` (shown in Manage profiles), `standard` or `automatic`; renaming cannot break an ID-based automation. `clear_adjustments: false` preserves temporary adjustments. Profile activation updates only the session journal and backup sequence, not the standards revision or HA’s five-revision history. Profiles support more than two manually/automatically selected room conditions; no sensor interpolation is implemented.

The schema 2 collection adds `brightness: {game_sdr, movie_sdr}`, `profiles: [{id, name, brightness?}]`, and `automatic: {bright: profile_id, dark: profile_id}`. `bank.settings` remains Base; `bank.variants[profile_id]` holds only overrides. There is one authoritative brightness store. Snapshot `preferences` projects the three legacy slider values for compatibility: Base gaming, automatic-bright movie and automatic-dark movie. All named data and the selection are in the complete MQTT backup.

Install HA 0.8 before enabling schema 2. On connecting to bridge API 6, HA requests the idempotent `upgrade_profiles` migration. The TV editor offers the same migration for standalone use. Migration preserves native targets, effective Bright/Dark values and temporary adjustments without any native write. Schema 1 imports remain supported and are upgraded on the next companion sync. The earlier schema 1 backup remains in HA’s standard history.

Catalog commands use the current `revision`. `create_profile` takes `name` and optional `copy_from` and returns a random stable `profile_id`; rename/delete/reset take `profile_id`. Reset removes all overrides. `set_automatic` takes `profiles: {bright, dark}`. `apply_profile` takes `profile_id`, optional `clear_adjustments` (default true), and optional `revision`. Names are unique, limited to 64 characters; up to 32 named profiles are allowed. Catalog metadata changes add no native polling or background timers.

## Storage and recovery

`/var/lib/io.github.andrewkennedy.lgpicturebridge/profiles.json` contains a schema 2 collection (native base banks, named partial overlays, shared brightness and automatic bindings), owner ID, revision and enabled state. Explicit edits use atomic replacement with fsync. A separate small `profile-session.json` records dirty bank/key membership, pending restores, boot ID, power, selected profile, ambient room and the last applied profile environment. Repeated values for an already dirty slider do not rewrite that journal. These are ordinary app files, never system partitions.

Values stay in RAM and are also backed up through MQTT. On a same-boot service restart, only dirty banks are read to reconstruct temporary values from LG's saved settings. Confirmed native standby or a changed kernel boot ID schedules restoration of dirty scopes. Unknown/disconnected states, format changes, Screen Off and Screen Saver do not end a viewing session. Native power states follow the [lgtv2 power-state documentation](https://github.com/hobbyquaker/lgtv2/blob/master/README.md); model-specific behavior should be verified during installation.

Restores persist intent before writing, use compare-and-set reads and exact native scope/readback checks, and write differences only. Interrupted work remains queued. Retries back off from 5 seconds to 5 minutes only while recovery has failed and the TV is on; there is no additional healthy-state polling. A newer manual change cancels an older pending restore for that key and becomes a temporary adjustment for the current session.

Native preset transitions do not reapply profiles. Day/night context is supplied retained by HA on `<base>/profiles/environment` (`{"protocol":1,"room":"dark"}`). While HA is unavailable the TV keeps the last known room context. On reconnect it receives the current sun state. Existing temporary adjustments survive automatic room transitions. A manual profile selection ignores changes in room context until Automatic is selected again.

## Complete backup envelope

`<base>/profiles/backup` is retained and contains:

```json
{"protocol":1,"format":"lg-picture-bridge-backup","state_json":"<complete JSON state>","sha256":"<SHA-256 of the exact UTF-8 state_json bytes>"}
```

The decoded state contains `schema`, `owner_id`, `instance_id`, `sequence`, `revision`, `document`, `preferences`, `enabled`, `room`, `selection`, `active_profile`, `environment`, `overrides`, `recovery`, `migration_id`, `context` and `created_at`. `document` includes all saved native banks, named profile overlays, shared brightness, automatic bindings and device bindings. `recovery` includes dirty keys, pending restore scopes, boot ID and power. `reconstructing` explicitly marks a startup snapshot whose temporary values have not yet been read back. No account secrets, broker passwords, firmware or unrelated system configuration are included.

Backups are emitted after changes (at most twice per second during adjustment bursts), at power transitions, on broker reconnect and HA discovery refresh. Full snapshots are not embedded in entity attributes or sent with the bridge heartbeat. A SHA over the exact JSON text avoids cross-language float/canonicalization differences. It detects corruption; it is not an authentication signature. Broker access control protects this local protocol.

HA commits the envelope using its native atomic Store, then publishes a non-retained acknowledgement on `<base>/profiles/backup/ack` with `owner_id`, `instance_id`, `sequence`, and `sha256`. Only the current snapshot's matching acknowledgement marks it backed up. Duplicate snapshots are acknowledged without rewriting HA storage. Old sequences and snapshots from a different non-live process cannot replace the saved copy. HA also keeps the last five standard revisions, plus the complete legacy HA-owned document during migration.

In the Home Assistant panel, **Profiles & backup → Download backup** exports the complete envelope. The TV app omits file import/download controls because its browser file handling is unsupported; automatic MQTT backups continue independently. Importing a backup deliberately restores its standards and preferences and queues verified native restoration; historical temporary deviations are not replayed into a new viewing session. They remain available in the backup for inspection. Download/upload and the HA `export_profiles`/`import_profiles` actions also support schema 1 legacy and schema 2 named-profile standard documents; the HA actions additionally accept/export YAML.

## Migration

For an older HA-owned collection, first use companion 0.3.2 with bridge 0.13.2 or newer. That companion preserves its entire previous Store as `legacy`, stops HA-side policy execution, and waits for API version 2. If the TV has no collection, HA imports the existing standard document unchanged, the three current helper values, temporary adjustments, and pending restore scopes. The migration ID makes an identical retry harmless. Migration completes only after HA has saved a matching TV backup. A pre-existing TV collection is never silently replaced by HA's old copy. Once the TV owns the collection and HA has its complete backup, upgrade the companion to 0.4 or newer. Its entry migration removes helper bindings while preserving standards and brightness preferences. Move external references to the built-in number entities before deleting old helpers.

Before the updated TV is reachable, the HA integration reports `awaiting_tv_migration`. Existing native settings remain on LG's saved banks; temporary restoration/day-night management resumes after migration. Downloadable backups remain available while the TV is offline, but edits require the TV because it is the sole authority. Do not edit live HA `.storage` manually.

## API

`/profiles/status` advertises transport `api_version:2` and a compact `manager` status. Manager `editor_api:9` separates browsing from managed standards, adds complete native snapshots, and accepts compared native-only edits. API 8 added native catalog discovery and `inspect_many` (1–32 bank IDs), with shared request-local description reads. API 7 added per-setting inheritance removal in `edit_many`; API 6 added named profiles; `profile_schema` advertises the current collection format. API 5 added brightness linking, motion-control enrollment and filtered restoration. Version 4 supports ordinary scope editing; versions below 4 remain read-only in the editor. Commands use protocol 1, current `session_id`, a unique `request_id`, and an expiry within 60 seconds, never retained. Supported actions: `get`, `inspect`, `inspect_many`, `include_native_catalog`, `capture_native`, `compact_management`, `initialize`, `import`, `edit`, `edit_many`, `set_enabled`, `set_brightness`, `set_brightness_links`, `include_motion_controls`, `set_environment`, `restore`, `restore_scope`, `save`, `reconcile`, `backup`, `restore_backup`, `upgrade_profiles`, `create_profile`, `rename_profile`, `delete_profile`, `reset_profile`, `set_automatic`, `apply_profile`.

`edit_many` carries an expected `revision`, an `edits` array of `{bank_id, variant, settings?, inherit?, expected?}` patches and an optional shared `preferences` patch. `inherit` is a list of existing managed keys whose overrides should be removed from the named `variant` (never Base). It can accompany ordinary `settings` for different keys. Duplicate or conflicting set/remove operations reject the entire batch. Resetting an already inherited key is a storage no-op. Every target/value is validated before committing the batch. Native-only keys require `expected` values from the review read. Managed changes use one atomic standards-file replacement; native-only writes use a small transient journal removed after verified completion. A changed native value is preserved rather than overwritten by replay. Duplicate targets, conflicting shared brightness values, stale revisions and power-session changes reject the batch without partial commitment. Unchanged standards cause no file write or revision. Native application remains sequential, compare-and-set, verified and journaled; it is not a hardware transaction.

Editor `restore` and `save` commands carry `selection: {bank_id: [key, ...]}`, `revision` and the reviewed `room` plus `profile_id` for schema 2 collections. `save` also carries `expected: {bank_id: {key: temporaryValue}}`. This freezes the selected keys and rejects adjustments or room context that changed after review. Legacy callers can still use `scope: active | all | bank_id`.

The TV app uses its permission-scoped Luna `profiles` method. The HA editor uses an authenticated admin WebSocket command. No new HTTP server, credential prompt, cloud dependency or background UI polling is needed. The shared sources are `app/profile-editor.js` and the pure presentation model `app/profile-view.js` (including the target-grid coordinates and Cartesian target matching); the HA repository vendors both with checked SHAs via `scripts/sync-editor.py`.

`set_brightness_links` accepts `revision` and `links: [{bank_id, linked}]`. Every target, base brightness and every named profile’s value are validated before one standards commit. Independent profiles remove `brightness_role`, using existing native values and room variants; no second settings store is added.

`restore_scope` accepts `revision`, optional `scope: all | active`, `filters` (`port`, `input_type`, `format`, `family`, `preset`, `genre`, `allm`, each a nonempty list) and optional `categories` (`picture`, `motion`, `game`, `port`, `selection`). It uses the same pure grouping model as both editors, expands linked brightness, checks applicability before queuing writes, and returns exact `selection` and `excluded` values. Unknown filters and empty matches fail; source/room/power changes during inspection abort. This applies existing active-profile standards; it does not select a source or create source-dependent picture recipes.

Native browsing requires the reviewed controller/model and an online TV. Install companion 0.10 before bridge 0.19 to validate the separate native snapshot. Collections allow up to 768 banks and 500 KB; complete backups retain the 750 KB state limit. `compact_management` removes copied Base keys only after a complete native backup has been acknowledged by HA, with an explicit revision-checked keep map. Overlay, linked-brightness and pending temporary/recovery keys are always retained. Migration does not write LG values. Keep selections should be derived from the pre-expansion collection plus intentional edits since expansion; bank-name prefixes alone are not reliable provenance.

The MQTT client reserves a bounded 1 MiB packet plus 256 KiB of following status/discovery traffic. A single retained backup is sent once per connection/checksum; announcement, subscription acknowledgement and HA availability callbacks do not resend the same large snapshot. This avoids startup reconnect loops while an expanded pre-compaction collection and its complete native snapshot are both backed up.
